# 代码画廊 · 定时同步配置（一次性）

> **一次性运维文档**。做完这一次，之后同学合并作品会自动同步，不需要再碰。
> 目标：把「GitHub 定时任务被延迟到 2~5 小时」这个问题，换成「Cloudflare 每 5 分钟准点触发」。
> 全程约 10 分钟，不需要改仓库代码。

---

## 0. 这件事在干什么

```
Cloudflare Cron（每 5 分钟）
   └─→ 调 GitHub API：workflow_dispatch
          └─→ 触发 .github/workflows/deploy.yml
                 └─→ 拉 AtomGit 作品仓库 → 提取 → 构建 → 部署到 Pages
```

Worker 只负责"敲门"，构建和部署仍在 GitHub Actions 里跑，所以 Pages 免费配额依旧由
部署前的「产物指纹守卫」保护：产物没变就不部署，不会白花配额。

---

## 1. 建一个细粒度 PAT（个人访问令牌）

1. 打开 https://github.com/settings/personal-access-tokens/new
2. 填：
   - **Token name**：`osc-gallery-sync`
   - **Expiration**：90 days（到期前记得续，见第 6 节）
   - **Resource owner**：你自己的账号
   - **Repository access** → `Only select repositories` → 勾选 **OSC-Harmony1024-Gallery**
   - **Permissions → Repository permissions** → 找到 **Actions** → 改成 **Read and write**
     （其余权限全部保持 No access）
3. 点 **Generate token**，**立刻复制**（只显示一次），形如 `github_pat_xxx`。

> 这个令牌只够「触发 Actions」，读不到代码、改不了仓库，泄露风险可控。

---

## 2. 部署 Worker

### 路线 A：Cloudflare 后台（不用装任何东西，推荐）

1. 打开 https://dash.cloudflare.com → 左侧 **Workers & Pages**
2. **Create** → **Workers** → **Create Worker** → 名字填 `osc-gallery-sync` → **Deploy**
3. 点 **Edit code**，把 `scripts/cloudflare-cron-worker.js` **整份内容**粘进去（覆盖默认代码）
4. 右上角 **Deploy**

### 路线 B：命令行 wrangler

```bash
npx wrangler login
npx wrangler secret put GH_TOKEN --config scripts/wrangler.cron.toml   # 粘贴第 1 步的令牌
npx wrangler deploy --config scripts/wrangler.cron.toml
```

`wrangler.cron.toml` 里已经写好了仓库、工作流文件名和 `*/5 * * * *` 的定时。

---

## 3. 配置变量与密钥（后台路线必做）

Worker 页面 → **Settings** → **Variables and Secrets**，逐个添加：

| 名称 | 类型 | 值 |
| :--- | :--- | :--- |
| `GH_TOKEN` | **Secret（加密）** | 第 1 步复制的 `github_pat_...` |
| `GH_REPO` | Text | `CapableCCat/OSC-Harmony1024-Gallery` |
| `GH_WORKFLOW` | Text | `deploy.yml` |
| `GH_REF` | Text | `main` |
| `MANUAL_KEY` | Text（可选） | 随便一串，比如 `osc-1024`，用于手动触发自测 |

填完点 **Deploy** 让变量生效。

---

## 4. 打开定时触发器

Worker 页面 → **Settings** → **Trigger Events** → **Cron Triggers** → **Add Cron Trigger**：

```
*/5 * * * *
```

（Cron 用 UTC，但 `*/5` 与本地时区无关；免费版支持 1 分钟粒度，每 5 分钟 ≈ 288 次/天，
远低于 Workers 免费额度。）

---

## 5. 验证（三步，缺一不可）

**① 手动触发一次**

浏览器打开（把域名和 key 换成你自己的）：

```
https://osc-gallery-sync.<你的子域>.workers.dev/?key=osc-1024
```

期望返回：

```json
{ "ok": true, "repo": "CapableCCat/OSC-Harmony1024-Gallery", "workflow": "deploy.yml", "ref": "main", "triggeredAt": "..." }
```

**② 去 GitHub 看是否真的触发了**

https://github.com/CapableCCat/OSC-Harmony1024-Gallery/actions
应出现一条 **event = workflow_dispatch** 的运行，并且 `success`。

**③ 看线上数据是否更新**

```bash
curl -s "https://osc-harmony1024-gallery.pages.dev/data/works.json?cb=1" | head -c 200
```

`count` 应等于 AtomGit 作品仓库里实际的作品数（现在是 5）。

## 6. 常见问题

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 返回 `dispatch 失败 401` | 令牌无效 / 过期 / 没给 Actions 权限 | 重新生成 PAT，务必勾 **Actions: Read and write**，再更新 `GH_TOKEN` |
| 返回 `dispatch 失败 404` | 仓库名或工作流文件名写错 | `GH_REPO` 是 `owner/repo`；`GH_WORKFLOW` 是 **文件名** `deploy.yml`（不是标题） |
| 返回 `dispatch 失败 403` | 令牌权限不够或被限流 | 检查权限；等一分钟重试 |
| 手动能触发，但每 5 分钟不触发 | Cron 没保存 / 未重新 Deploy | 回到第 4 节确认 Trigger 存在；改完变量必须重新 Deploy |
| GitHub 上没有 `workflow_dispatch` 运行 | 工作流文件不在默认分支 | 确认 `main` 上有 `.github/workflows/deploy.yml` 且含 `workflow_dispatch:` |
| 90 天后突然不工作 | PAT 到期 | 重新生成并更新 `GH_TOKEN`（建议现在就设个日历提醒） |
| 想看 Worker 报错 | — | 后台 Worker → **Logs**，或命令行 `npx wrangler tail` |

## 7. 临时替代方案（不想建 Worker 时）

用任意支持 5 分钟粒度的定时服务（如 cron-job.org、UptimeRobot），让它定时 `POST`：

```
https://api.github.com/repos/CapableCCat/OSC-Harmony1024-Gallery/actions/workflows/deploy.yml/dispatches
Headers: Authorization: Bearer <PAT>, Accept: application/vnd.github+json
Body:    {"ref":"main"}
```

时效一样，但 PAT 存在第三方平台上，**安全性不如 Worker**（令牌在别人服务器里）。
仅作为应急，长期建议仍用 Worker。

## 8. 这个配置生效后，哪些地方会变

- 同学合并作品后，**几分钟内**自动上墙（在此之前是"碰运气，可能几小时"）；
- GitHub 的 `schedule` 仍然保留，只作为兜底——它不靠谱，但不要钱，留着不亏；
- 部署配额仍由「产物指纹守卫」保护：数据没变就跳过 `pages deploy`。
