## O-01 主色调改为彩虹调色

- **现状**：全站单一深色主题 + 单强调色 `#3fd0a8`（基线 `D-05` 与全局铁律 6「视觉已定稿」）。浅色主题令牌以注释形式保留在 `client/src/index.css` 末尾，仅备查、不启用。
- **建议**：
  1. 不直接改 `index.css`；先做一次配色评审，明确彩虹色是「作品分类色」还是「全局主色」。语言标签已有五色（`--lang-*`），若全局再加一整条彩虹，会与语言标签抢注意力。
  2. 若确定要改：走基线 V1.1、登记变更记录，再动 `client/src/index.css` 的 `@theme` / `:root` 语义变量（前端只认 `var(--app-*)`，改变量即可全站生效）。
  3. 若一并复议浅色主题，需要同时解决「白底作品与深底作品同屏」的老矛盾（`D-05` 当初就是因为这个关掉夜间切换）。
- **代价与影响**：影响全站视觉与既有定稿；「纸面衬边」（`D-04`）的取值要重新评估；历史截图与文档插图会过时。
- **优先级**：P2，1024 期间不做。

## O-02 混排时页头 WORKS 计数把示例数据算进去

- **现状**：`App.jsx` 传给 `Header` 的是 `works.length`，真实作品与 `mock: true` 的示例混排时会被算成一个总数（例如 `014 WORKS` 里只有 1 件是真实提交）。
- **建议**：口径由用户定，二选一 ——
  1. 页头只统计真实作品，示例另计（如 `001 WORKS · 013 示例`）；
  2. 保持总数，但文案改为「作品 / 示例」分列。
  落点都在 `Header.jsx` 的 props 与 `App.jsx` 的计数，纯展示改动。
- **代价与影响**：`Header` props 需要扩展；文案与布局微调；无行为风险。
- **优先级**：P2（取决于是否长期混排）。

## O-03 iframe 类作品放大后内容两侧留白

- **现状**：html / js 作品在卡片里是 iframe 直渲，学生页面多为固定宽度居中；整行展开后卡片变宽、页面内容不跟随，两侧出现大面积空白（观感上像"空了"）。
- **建议**：给 iframe 预览一个统一的「演示画幅」（如 16:9 居中 + 底色），把随机黑边变成规则留白；跨域/沙箱拿不到内容真实宽度，只能给固定画幅，不能按内容自适应。
- **代价与影响**：改 `FrameStage.jsx` 的容器；对所有 html/js 作品生效，需要回归窄卡状态下的观感。
- **优先级**：P3 观察项（等真实 html 作品上站后再看是否值得做）。

## O-08 iframe 常驻与基线 F-03「离开视口可卸载」不符

- **现状**：`useInView` 默认 `once: true`，`FrameStage` 与 `CodePane` 都用默认值——一旦进入过视口就永久保留。基线 F-03 的要求是「进入视口才挂载，离开视口可卸载（防上百 iframe 拖垮浏览器）」。作品上百件时，所有看过的 iframe 会一直活着。
- **建议**：分两步，先量后改——
  1. 用 Performance/Memory 面板在 50+ 卡片场景下量一下常驻 iframe 的实际占用；
  2. 若确实显著，把 `FrameStage` 改成 `once: false`，但**卸载时保留外层占位高度**、重进视口时重建（代价是学生代码会重新执行一次，动画类作品会重头播）。
- **代价与影响**：改 `useInView` 调用参数与 `FrameStage` 生命周期；重进视口会重跑作品，可能产生"动效重播"的观感副作用，需要产品取舍。
- **优先级**：P2（等真实作品数量上到几十件再评估）。

## O-09 新增动效未尊重 `prefers-reduced-motion`

- **现状**：`index.css` 已对 `.card-in` 和 `body::before` 做了 `prefers-reduced-motion` 处理，但这次新增的卡片放大/收起动效走的是 Web Animations API（`WorkCard.jsx` 的 `toggleCard` / `useEffect`），**没有做同样的判断**。
- **建议**：在 `WorkCard` 里加一个常量 `const reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches`（或封装成 `lib/motion.js` 的 `canAnimate()`），为真时跳过 `el.animate(...)`，直接切换布局。
- **代价与影响**：约 6 行；对普通用户无影响，对开启"减少动态效果"的用户（含晕动敏感人群）更友好。
- **优先级**：P2（项目已有视觉克制的既定取向，这条属于同一取向的延续）。

## O-10 首屏 JS 370KB：highlight.js 改按需加载

- **现状**：`client/dist/assets/index-*.js` 单块约 **370KB（gzip 126KB）**，`CodePane.jsx` 在模块顶层 `import hljs from 'highlight.js/lib/core'` 并注册了 6 种语言，全部进首屏包；而代码高亮本来就要等卡片进入视口才执行。
- **建议**：把 `hljs` 与语言包改成动态 `import()`（在 `useInView` 命中后按 `meta.hljs` 加载），首屏只保留 React + 卡片骨架；或按语言拆成独立 chunk。
- **代价与影响**：首屏预计可减 100KB 以上（gzip 约 40KB）；代价是高亮会晚一拍出现，需要保留 `…` 占位（`CodePane` 已有）；异步加载需处理竞态（快速滚动时）。
- **优先级**：P2（移动网络下收益明显）。

## O-11 Pyodide 的 CDN 兜底与 D-02 冲突

- **现状**：`client/public/py.worker.js` 里 `loadFrom(CDN_BASE)` 作为自托管失败后的兜底。但 D-02 明确记录了「公共 CDN 实测 8.6MB wasm 下载 51s，首屏必超时」——兜底路径基本等于"静默降级成必然超时"。
- **建议**：要么删掉兜底、失败时直接报错（让问题显性化），要么保留但 `console.warn` 明确提示"已降级到公共 CDN，可能超时"。落点都在 `py.worker.js` 的 `init()`。
- **代价与影响**：几行；删兜底会让自托管文件缺失时直接报错（更容易发现部署漏文件）。
- **优先级**：P2。

## O-12 Python 运行时无条件预热 12MB

- **现状**：`App.jsx` 只要数据里有任意 `pyodide` 作品，就在 `requestIdleCallback` 里下载约 12MB 运行时；而 `WorkCard` 本身已有"悬停即预热"（`onPointerEnter`）。对从没打算点运行的访客（尤其手机流量），这 12MB 是白花的。
- **建议**：改成"首个 Python 卡片进入视口 + 悬停/聚焦"才预热，或在 `navigator.connection.saveData` 为真时跳过。
- **代价与影响**：改 `App.jsx` 的预热 effect 与 `FrameStage`/`WorkCard` 的观测逻辑；预热更晚意味着首次点击运行可能多等 1~2 秒（有悬停预热兜底）。
- **优先级**：P2。

## O-13 两套 ANSI 实现（ansi-to-html + 自研屏幕）

- **现状**：`OutputPane` 走两条路径：含光标指令 → 自研 `ansi-screen.js`；普通输出 → `ansi-to-html` 依赖。两套解析器语义不完全一致（SGR 覆盖范围、行尾处理），维护时容易只改一边。
- **建议**：先用自研 `ansiToHtml()` 跑一批普通输出的回归对比（mock 里的 `mock-py-01` / `mock-c-02`），确认渲染一致后**删掉 `ansi-to-html` 依赖**，统一走自研屏幕；不一致就维持双路径并在两个文件头互相注明分工。
- **代价与影响**：少一个依赖（约 10~20KB）；若自研解析器在某个 SGR 上不如库完整，会出现回退，需要逐条比对；属于"删依赖"级别改动，建议单独一轮做。
- **优先级**：P2（精简项，不影响功能）。

## O-14 `mascot.png` 889KB

- **现状**：`client/public/mascot.png` 889KB，只在空状态页（`EmptyGallery`）出现，但一样会被访问者下载。
- **建议**：转 WebP/AVIF（同尺寸预计 100~200KB），用 `<picture>` 保留 png 兜底；或按显示宽度（256px）生成 2x 图。
- **代价与影响**：纯资源替换；注意 CSS 里"裁掉底部 30% 水印"的 `aspectRatio` 与 `object-top` 需要跟着新图核对。
- **优先级**：P2。

## O-15 `index.html` 缺 favicon / description / og

- **现状**：`client/index.html` 只有 charset / viewport / theme-color / title，没有 favicon，也没有 description 与 og/twitter 卡片信息。分享链接到群里时没有缩略图与摘要。
- **建议**：加一个内联 SVG favicon（可直接复用站头的 `</>` 标记，零额外请求）、`<meta name="description">`、`og:title/og:description/og:image`（可用 `mascot.png` 或单独做一张 1200×630 图）。
- **代价与影响**：纯 head 改动；og:image 需要一张 1200×630 的资源（可以先不加图，只加文案）。
- **优先级**：P2（活动传播期收益直接）。

## O-16 仅改文档也触发完整构建部署

- **现状**：`deploy.yml` 的 `push` 触发没有路径过滤，改一个 `.md` 也会跑完整的「clone 作品仓库 → 提取 → 构建 → 部署」，占用构建配额（见 O-04）。
- **建议**：给 `push` 加 `paths-ignore: ['docs/**', '**.md', '.gitignore', 'LICENSE']`（保留 `workflow_dispatch` 手动触发）。
- **代价与影响**：一行 YAML；注意如果将来把文档也纳入站点展示，需要回退这条。
- **优先级**：P3（与 O-04 一起做收益最大）。

## O-17 重复的按钮样式常量与未使用设计令牌

- **现状**：
  - `WorkCard.jsx` 的 `ACCENT_BTN` 与 `OutputPane.jsx` 里"放大/关闭"按钮的样式各写一套，改一处容易漏另一处；
  - `index.css` 里 `--app-accent-soft`（含 `--color-accent-soft` 映射）全站无人使用；`--app-code-*` 仅供 hljs 主题使用，没有多余项。

- **代价与影响**：纯重构，无行为变化；需要回归放大/关闭/重跑/查看源码 4 个按钮的观感。

## O-04 定时频率与 Pages 免费构建配额（已落地：30 分钟 + 产物指纹守卫）

- **现状**：`.github/workflows/deploy.yml` 里 `cron: '*/30 * * * *'`，一天最多 48 次；Cloudflare Pages 免费计划官方 Limits 页写的是 **500 builds/月**（并发构建 1）。48×30 = 最多 1,440 次，**远超配额**。配额打满后新构建会被拒绝到月底（已部署站点不受影响，但新作品上不了墙）。
- **建议**（按成本从低到高）：
  1. ~~把 cron 降到 `0 */2 * * *`~~ —— 被否决：活动期（1024 前后一周）是提交高峰，30 分钟时效要保住；
  2. workflow 里加一步「数据指纹对比」：`works.json` 与上次部署一致就跳过 deploy（需要把上次的 hash 存到 Variable 或 commit 里）；
  3. 或者改成"活动期间手动 Run workflow + 整点一次"。
- **代价与影响**：只改 `deploy.yml`（+ 可选一个轻量脚本）；改 cron 属于一行改动、零风险；自动跳过部署需要引入状态存储（与零后端不冲突，状态放 CI 侧）。
- **优先级**：**P1**（属于运营风险，活动期间会踩到）。

## O-05 非 UTF-8（GBK）源码解码（已落地：UTF-8 严格 → GBK 回退）

- **现状**：`scripts/generate-data.js` 全程用 `fs.readFileSync(file, 'utf8')`。Windows 同学用记事本/旧 IDE 存成 GBK 时，中文注释会变成 `锟斤拷`，HTML 里的资源引用也会解码失败导致内联漏掉（白屏）。
- **建议**：在 `generate-data.js` 里加一个 `readText()` 工具：先按 `Buffer` 读入，用 `TextDecoder('utf-8', { fatal: true })` 尝试解码，抛错则回退 `TextDecoder('gbk')`（Node 22 自带 full-icu，支持 gbk）；`inlineHtml`、`readTitle`、`collectReferencedFiles` 三处统一走它。
- **代价与影响**：只动提取脚本，不动前端与数据契约；新增约 15 行；需补一条 GBK fixture 用例（本地自造，不碰真实提交）。
- **优先级**：**P1**（真实提交越多样，踩中概率越高）。

## O-07 交接文档参数错误（已落地：改正 §七）

- **现状**：交接文档「七、关键词速查」写 `scripts/generate-data.js（--repo / --allow-empty / --no-mock）`，但脚本的 `parseArgs()` 只认 `--repo / --out / --repo-url / --concurrency / --no-mock / --help`；空数据放行实际由 workflow 里的 `ALLOW_EMPTY` 环境变量控制。基线 `D-10` 里也提到 `--allow-empty`，但那是历史决策记录（冻结、不改），机制已换成 env。
