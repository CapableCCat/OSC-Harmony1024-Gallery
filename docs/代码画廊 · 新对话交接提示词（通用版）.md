## 一、项目基本盘

- **项目**：1024 代码画廊 —— 天津中德开源鸿蒙社程序员节作品展。同学提交各语言
  「Hello OpenHarmony」，站点把代码真的跑起来给人看。
- **仓库**（两个，互相独立）：
  - 展示站：GitHub `CapableCCat/OSC-Harmony1024-Gallery`（本仓库）
  - 作品：AtomGit `tsgu-osc-org/1024`（CI 用 `git clone` 拉取，**不是** actions/checkout）
- **架构**：**零后端**（D-01）。纯静态，部署 Cloudflare Pages。
  - HTML/JS → `iframe` 沙箱直渲（sandbox + CSP）
  - Python → Pyodide（自托管 11.7MB，Worker 内执行，5s 超时回收）
  - C/C++ → 构建期 gcc 编译预执行，前端回放真实输出（含 ANSI）
- **线上**：https://osc-harmony1024-gallery.pages.dev/
- **技术栈**：React 19 + Vite 8 + Tailwind v4（无 config，令牌在 `index.css` 的 `@theme`）、
  Node 22、npm workspaces（只有 `client`）。
- **文档**：`docs/README.md` 是文档地图；需求基线与数据规范是两份事实源。

## 四、环境与坑

- **用户终端是 PowerShell 5.1**：验证命令必须单行、优先 `Invoke-RestMethod`；
  **不要给 `curl.exe -d '{...}'`**（PS 篡改引号），需要发 JSON 就写临时文件 `--data-binary "@file"`。
- **vite dev/preview 监听 IPv6**：探活用 `http://localhost:5173`，`127.0.0.1` 会 502。
- **本机 gcc 是 MinGW 8.1，CI 是 gcc 13**：学生用新语法的 C++ 可能本地编不过、CI 能过，以 CI 为准。
- **本地跑真实 C/C++ 作品 = 执行陌生二进制**：本地测试只用自造 fixture，真实提交的预执行交给 CI。
- **bash 里 `node -e "..."` 内嵌模板字符串/反引号极易转义炸裂**（本项目真实踩坑）：
  改文件优先用编辑工具，非要脚本化就写成临时 `.mjs` 文件再执行。
- **Tailwind v4 无 `tailwind.config.js`**：加设计令牌去 `client/src/index.css` 的 `@theme`；
  语义色全部是 `var(--app-*)` 间接引用，主题切换只改变量。
- **运行时/字体必须自托管**：`npm run vendor:pyodide`、`npm run vendor:fonts` 已纳入 `build`。

## 五、全局铁律

1. **零后端不动摇**（D-01）：不加服务器、不加数据库、不做需要存储的功能。
2. **绝不修改同学提交的代码**（D-04）：展示差异用容器/样式解决，不动 `code` 内容。
3. **PR 未合并的作品不上墙**（D-09）；需要「审核中」展示时用 `staged/` 目录约定，不爬 PR。
4. **不依赖 AtomGit API**（D-10）：实测 404，端点不可用。
5. **数据契约变更流程**：先改《数据规范》→ 再改 `generate-data.js` 的 `normalize()` → 最后改前端；字段只加不改名。
6. **视觉已定稿**：深色仪表盘风，单强调色 `#3fd0a8`；不加网格/发光/循环动效/3D。
7. **性能红线**：视口外不挂 iframe；不加 backdrop-blur；运行时下载避开首帧。
8. **AI 绝不主动 commit/push**；用户说「提交」= add + commit + push 三步全做。
9. **提交规范**：全英文 title + 中文 body（问题、改动、影响、验证），按功能粒度拆分。
10. **交付必附 PowerShell 5.1 友好的验证指引**。
11. `package.json` 的 `build` 包含数据生成——**CI 里构建前必须先跑带 `--repo` 的提取**，
     否则 mock 会覆盖真实数据（这就是 `build:site` 存在的原因）。

## 六、协作规则

- **单功能节奏、逐点确认**：完成一个任务点后停下等确认，不越点开发。
- 交付必须附**验证步骤**（适配 PowerShell 5.1）。
- **任务文档与代码同步更新**：改了行为就改对应文档（文档地图见 `docs/README.md`）。
- **需求与红线查基线**：任何「要不要做 X」先看 D-01~D-10 有没有否决记录。
- 用户是「先审阅 → 再说继续/提交」的节奏；**禁止越点开发**（除非明确说"继续全部"）。
