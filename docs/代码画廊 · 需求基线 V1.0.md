## 一、项目定位

天津中德开源鸿蒙社「1024 程序员节」作品展示网站。同学们提交各种语言的
「Hello OpenHarmony」代码作品，本站以卡片网格形式展示，并且**让代码真的在网页里跑起来**，
而不是截图。

- 项目名：OSC-Harmony1024-Gallery
- 单页、纯静态、无后端、无数据库
- 访客无需登录，无任何写操作

## 二、目标用户与使用场景

| 用户 | 场景 |
| --- | --- |
| 校内同学（访客） | 活动期间浏览作品墙、点击「运行」看输出、跳转作品仓库围观 |
| 社团维护者（你 + 辅助同学） | 在 GitHub 网页上配置开关、手动/自动触发更新；不写代码也能运营 |
| 提交作品的同学 | 向 AtomGit 作品仓库提交 PR，合并后作品自动上墙 |

## 三、功能需求

### F-01 作品墙
卡片网格布局，`repeat(auto-fill, minmax(320px, 1fr))` 响应式。每卡含：编号、作者、
标题或文件名、语言标签、运行区、操作栏（源码跳转 / 复制 / 运行）。

### F-02 语言识别与三种执行器
语言只认 `html` / `js` / `python` / `c` / `cpp`，执行器由语言推导：

| 语言 | 执行器 | 行为 |
| --- | --- | --- |
| html / js | `iframe` | 沙箱内直接渲染，`sandbox="allow-scripts"` + srcdoc 注入 CSP |
| python | `pyodide` | 浏览器内 CPython（WASM）真执行，运行于独立 Worker |
| c / cpp | `cached` | 构建阶段编译执行，前端回放真实 stdout/stderr（含 ANSI 颜色） |

### F-03 沙箱直渲
iframe 仅 `sandbox="allow-scripts"`（无 `allow-same-origin`）；srcdoc 注入 CSP：
禁 `connect-src` / `form-action` / `frame-src`，仅放行内联资源与 https CDN。
进入视口才挂载，离开视口可卸载（防上百 iframe 拖垮浏览器）。

### F-04 Python 浏览器内执行
Pyodide 运行时**自托管**（不走公共 CDN），全局单例 Worker；单次执行超时 5 秒，
超时直接 `terminate()` 回收；支持空闲预热与悬停预热。

### F-05 C/C++ 预执行
提取阶段以源码目录为工作目录编译（20s 超时），以临时目录为工作目录运行（5s 超时，
`SIGKILL`）；捕获 stdout / stderr（含 ANSI 颜色代码）与超时标记。编译失败原样保存报错。

### F-06 运行状态机
`idle → waking → running → done / error / timeout` 六态，由按钮文案与输出区呈现，
不设独立状态行。

### F-07 代码与输出双视图
非直渲卡片默认显示代码预览（超过 8 行折叠，可展开）；运行后可切换查看输出。

### F-08 筛选与搜索
按语言筛选（带计数）；按作者 / 文件名 / 奖项关键字搜索。作品编号跟随作品本体，不随筛选变化。

### F-09 源码跳转与复制
卡片提供 `repo_url` 跳转（AtomGit 作品仓库对应目录）与代码复制。

### F-10 mock 示例数据
开发期与活动前的示例卡，来自 `data/mock-works.mjs`：
- 逐条开关：`enabled: false` 下线单条
- 全局开关：`SHOW_MOCK`（本地环境变量 / GitHub 仓库 Variable）

### F-11 空状态页
作品仓库为空（活动开始前）时，展示看板娘插画 + 「作品正在路上」文案 + 作品仓库围观链接。

### F-12 数据自动提取
CI 从 AtomGit 拉取作品仓库并运行提取脚本，生成 `works.json`：
- 递归扫描，跳过 `.git` / `node_modules` 等；作者 = 第一层目录名；标题优先读同目录 README 一级标题
- HTML 单文件内联（link / script / img / CSS `url()` → 内联或 base64）
- 被 HTML 引用的文件不再单独算作品
- 提取产物含 `runner`、预执行 `output`、`title` 等字段（字段契约见《数据规范》）

### F-13 更新触发
push 展示仓库 / 手动 workflow_dispatch / 定时（活动期间每 30 分钟）三种方式触发
构建部署。作品仓库为空时照常部署空状态页（`ALLOW_EMPTY`）。

## 四、非功能需求

| # | 需求 |
| --- | --- |
| N-01 | **零后端**：纯静态站点，部署到 Cloudflare Pages，无服务器、无数据库、无跨域 |
| N-02 | **零预算**：不产生任何服务器/托管费用 |
| N-03 | **安全**：访客不可执行任意代码于服务器；iframe 双重隔离（sandbox + CSP）；Python 在 Worker 内限时执行；C/C++ 仅在构建机预执行，不跑在访客浏览器 |
| N-04 | **性能**：视口外不渲染；搜索不阻塞输入；运行时下载避开首帧；滚动路径上无模糊合成 |
| N-05 | **上线时限**：2026-10-26 前可用（活动节点） |
| N-06 | 界面为简体中文；代码与元信息可用等宽英文字体 |

## 五、冻结决策（D-xx，不可随实现推翻）

| # | 决策 | 背景 |
| --- | --- | --- |
| D-01 | **零后端**，否决「Node 代理 + Piston」 | Piston 需 `--privileged` + cgroup v2 + 持久卷，Render 免费版三者皆无；无可用云服务器，备案周期不可接受 |
| D-02 | Python 用 Pyodide 且**自托管** | 公共 CDN 实测 8.6MB wasm 下载 51s，首屏必超时 |
| D-03 | C/C++ 用**预执行回放**，否决浏览器实时编译 | 浏览器无 C 编译器；作品是静态的，输出可预生成 |
| D-04 | **不修改同学代码**：预览差异用统一「纸面衬边」解决 | 否决颜色反转（破坏作者配色）与降亮度（暗色作品变糊） |
| D-05 | **单一深色主题**（浅色令牌保留注释备查），移除主题切换 | 白底/深底作品同屏时，页面底色只能把矛盾从一端推到另一端 |
| D-06 | **无评奖体系** | `tag` 字段与渲染分支保留为占位 |
| D-07 | 先用 `*.pages.dev` 默认域名 | 自定义域名后补（校园网访问异常时启动） |
| D-08 | **不做点赞/投票** | 需引入存储与防刷，与零后端冲突；评审不依赖线上投票 |
| D-09 | **PR 未合并的作品不上墙** | 未过审作品不进展示池；`isPR` 预览缓做 |
| D-10 | 空仓库检测**不依赖 AtomGit API** | `api.atomgit.com/repos/...` 实测 404；以扫描结果为准，`--allow-empty` 放行 |

## 六、变更记录（相对原始需求 prompt）

| 原始条目 | 现状 | 原因 |

| 后端 Express + Piston 执行层 | 删除，改为 F-02 三执行器 | D-01 |

## 七、验收标准

1. 三种执行模式可各自演示：HTML 直渲可见画面；Python 输出含 ANSI 颜色；
   C/C++ 回放真实输出；错误态与超时态有明确提示。
2. 作品仓库为空时，CI 成功部署空状态页；有合并作品后，站点在 30 分钟内自动更新。
3. 筛选与搜索可用；编号不随筛选重排。
4. 生产构建无控制台报错；`SHOW_MOCK` 变量可控制示例卡上下线。

## 八、术语表

| 术语 | 含义 |
| --- | --- |
| works.json | 数据产物，前端唯一数据源（构建期生成于 `client/public/data/`） |
| runner | 作品的执行方式：`iframe` / `pyodide` / `cached` |
| 纸面衬边 | 预览外圈约 10px 的浅色边，用于统一白底与深底作品的视觉边界 |
| 空数据熔断 | CI 提取到 0 件作品且未放行 `ALLOW_EMPTY` 时终止部署 |
| 预执行 | 构建阶段编译并运行 C/C++，把输出固化进 works.json |
