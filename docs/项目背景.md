# 项目背景与目的
项目名：OSC-Harmony1024-Gallery（天津中德开源鸿蒙社1024程序员节代码画廊）
这是为高校“天津中德开源鸿蒙社”开发的一个 1024 程序员节活动作品展示网站。新同学们提交了各种语言的代码作品，核心要求是输出 “Hello OpenHarmony”。为了展示他们的创意，我们需要将主页做成**卡片瀑布流/网格**的形式，并且让这些代码能够**直接在网页里“运行”并看到输出效果**，而不是干巴巴的截图。

- 代码执行引擎：Piston (通过 Docker 部署，基于 RESTful API 调用)
- 数据源：前端读取本地 `works.json` (由我后续通过脚本从 AtomGit 仓库提取生成，当前你先用 Mock 数据模拟)

# 核心架构与功能说明（必须严格实现）
网页的核心是“卡片展示”，每张卡片代表一个同学的作品。根据语言不同，采用“混合渲染架构”：

## 1. 前端直渲层（针对 HTML/CSS/JS 作品）
- 如果作品语言是 `html` 或 `web`，卡片内部直接使用 `<iframe>` 渲染。
- 必须设置 `sandbox="allow-scripts"` 属性，防止同学代码访问父页面或执行危险操作。
- 代码内容通过 `srcdoc` 属性注入 iframe，或者在卡片加载时请求代码内容并渲染。这类作品零延迟，打开页面直接显示运行效果。

## 2. 后端执行层（针对 Python / C / C++ 等）
- 这类语言的卡片上放置一个“▶ 运行代码”按钮。
- 用户点击后，前端向后端发送请求（`/api/run`），后端代理请求到本地的 Piston 引擎（`http://localhost:2000/api/v2/execute`）。
- Piston 执行完毕后，将 `stdout`（标准输出）或编译错误返回给前端，前端将其展示在卡片的 `<pre>` 代码块中。
- 必须有完善的交互状态：`待运行`、`运行中(loading)`、`运行成功`、`编译/运行报错`。

### 💡 给你的一些额外提示

1. **关于 Piston 部署**：Agent 给你代码后，你需要在自己电脑或服务器上运行 `docker run -d --privileged -p 2000:2000 ghcr.io/engineer-man/piston`，然后进入容器安装 Python 和 C/C++（命令 Agent 会在 README 里生成，你也可以直接问我）。
2. **数据提取问题**：目前 Agent 是用 Mock 数据开发。等前端跑通了，你需要写个简单的脚本（Python 或 Node），利用 AtomGit 的 API 把仓库里的同学们的文件代码爬下来，生成真实的 `works.json` 丢给前端。
3. **HTML 直渲的隐患**：虽然加了 `sandbox="allow-scripts"` 很安全，但如果同屏出现太多同学的 `iframe`，可能会导致浏览器卡顿。后续如果卡，可以改成“点击后才渲染”的懒加载模式。
